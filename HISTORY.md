- Build steps: `aapt2 compile` res/ → `aapt2 link` (with `-A assets` to bundle assets, `-I android.jar`) → inject `classes.dex` into the linked APK via .NET `ZipArchive` → `zipalign` → `apksigner sign`
- **Gotcha:** `apksigner sign --key key.pem --cert cert.pem` fails ("Not an RSA, EC, or DSA private key") even though the PEM is valid PKCS#8 RSA (verified via plain `KeyFactory` in a throwaway Java snippet) — apksigner's PEM parser in this build-tools version chokes on it for an unclear reason. Fix: convert both PEM files to raw DER first (strip the `-----BEGIN/END-----` lines, base64-decode, write bytes) and pass `--key key.der --cert cert.der` instead — signs and verifies cleanly.
- **Gotcha (found 2026-09-23, caused real on-device bugs across v9.10/v9.11):** this machine's `aapt2.exe` writes `\` instead of `/` for any nested subfolder under `assets/` (e.g. `assets/spr/radio.png` → `assets/spr\radio.png`), which Android's asset loader can't resolve, silently breaking anything referencing files in that subfolder. Required extra step after every `aapt2 link`, before signing: rewrite any zip entry name containing `\` to `/` (open with .NET `ZipArchive`, delete+recreate the entry), then grep the final APK's entries for `\` to confirm zero remain. See the 2026-09-23 entry below for the full repro/fix.

**How to apply:** for future builds, reuse the installed SDK/JDK/smali-lib above rather than re-downloading. Always convert `key.pem`/`cert.pem` to DER before calling `apksigner sign`. The signing key must NEVER be replaced — resigning with a different key breaks update installs on the user's/girlfriend's phone and wipes save data.
